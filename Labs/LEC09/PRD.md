# Sonic 애니메이션 뷰어 PRD

## 1. 문서 목적

`PRE-PRD.md`를 바탕으로 pico2d 애니메이션 뷰어의 구현 범위, 재생 규칙, 검증 기준과 단계별 개발 계획을 정의한다. 이 문서는 개발 요구사항이며, 구현이나 커밋이 완료되었다는 의미는 아니다.

## 2. 제품 목표

`sonic-sprite.png`에 포함된 모든 동작 애니메이션을 확대하여 관찰할 수 있는 데스크톱 뷰어를 만든다. 사용자가 조작하지 않아도 모든 동작을 순서대로 재생하고 무한 반복한다.

## 3. 구현 범위와 산출물

- 언어 및 라이브러리: Python, pico2d.
- 캔버스 크기: 가로 1280 × 세로 720 픽셀로 생성한다.
- 실행 소스: `Labs/LEC09/sonic_animation_viewer.py` 단일 파일.
- 입력 자산: 같은 폴더의 `sonic-sprite.png`.
- 소스 파일 내부에 프레임 정보, 애니메이션 목록, 재생 상태, 렌더링 및 이벤트 처리를 구성한다.
- 추가 이미지나 외부 설정 파일 없이 실행한다.
- 개발은 단계별로 진행하며 최소 20개의 실제 개발 커밋을 남긴다.
- 모든 개발 및 수정 커밋의 메시지는 한국어로 작성한다. 파일명, 라이브러리명, 코드 식별자는 원래 표기를 사용할 수 있다.

## 4. 기능 요구사항

### FR-01. 스프라이트 로딩

프로그램 시작 시 소스 파일 위치를 기준으로 `sonic-sprite.png`를 읽는다. 실행한 작업 디렉터리가 달라도 이미지를 찾을 수 있어야 한다. 이미지 로딩에 실패하면 원인을 알 수 있는 오류를 출력한다.

### FR-02. 모든 애니메이션 정의

구현 시작 시 스프라이트 시트를 확인하여 동작 그룹, 그룹별 프레임 수, 프레임 순서와 잘라낼 영역을 조사한다. 조사 결과는 단일 소스 파일의 애니메이션 데이터로 명시한다.

모든 동작 그룹을 누락 없이 포함하고, 동일 동작의 프레임 순서는 시트의 배치와 동작 흐름에 맞게 정의한다. 프레임마다 크기나 간격이 다르면 개별 영역을 지정한다. 원본 이미지 좌표를 pico2d의 이미지 좌표 체계에 맞게 변환한다.

> 동작 이름, 총 동작 수, 프레임 좌표와 프레임 수는 PRE-PRD에 명시되어 있지 않으므로 실제 이미지 조사 후 확정한다.

### FR-03. 동작별 5회 반복

한 동작의 첫 프레임부터 마지막 프레임까지 재생하면 1회 완료로 계산한다. 같은 동작을 정확히 5회 완료한 다음 대기 상태로 전환한다. 프레임이 하나인 동작도 정해진 프레임 표시 시간만큼 표시하면 1회로 계산한다.

### FR-04. 동작 사이 1초 대기

5번째 반복의 마지막 프레임을 정해진 시간만큼 표시한 후 1초간 대기한다. 대기 중에는 해당 동작의 마지막 프레임을 유지한다. 대기 시간이 끝나면 다음 동작의 첫 프레임부터 재생하며 반복 횟수를 초기화한다.

### FR-05. 전체 목록 무한 순환

정의된 목록 순서대로 모든 동작을 재생한다. 마지막 동작도 5회 재생 및 1초 대기를 마친 다음 첫 동작으로 돌아간다. 사용자가 종료할 때까지 순환한다.

재생 흐름: `동작 A × 5 → 1초 대기 → 동작 B × 5 → 1초 대기 → … → 마지막 동작 × 5 → 1초 대기 → 동작 A`.

### FR-06. 확대 표시

원본 픽셀 크기보다 충분히 확대하여 캐릭터의 움직임을 쉽게 구분할 수 있게 한다. 가로·세로 비율을 유지하고, 가장 큰 프레임도 화면 안에 표시한다. 캐릭터의 기준점을 일관되게 맞춰 프레임 크기가 달라져도 위치가 불필요하게 흔들리지 않도록 한다.

### FR-07. 시간 기반 재생

프레임 전환과 대기는 경과 시간을 기준으로 처리한다. 대기 중에도 이벤트 처리와 화면 갱신을 계속한다. 반복 완료 시점을 명확히 처리하여 마지막 프레임이 생략되거나 반복 횟수가 틀어지지 않게 한다.

### FR-08. 종료 처리

창 닫기와 ESC 입력으로 종료한다. 재생 또는 대기 상태 모두에서 종료할 수 있어야 하며, 종료 시 캔버스를 정리한다.

## 5. 초기 구현 기본값

캔버스 크기는 요청에 따라 1280 × 720 픽셀로 지정한다. 나머지는 PRE-PRD에서 정하지 않은 항목에 대한 초기 구현 제안이며, 실제 시트와 육안 검증 결과에 따라 조정할 수 있다.

| 항목      | 초기 설정                                                 |
| --------- | --------------------------------------------------------- |
| 캔버스    | 가로 1280 × 세로 720 픽셀 (`open_canvas(1280, 720)`)   |
| 재생 속도 | 초당 10프레임, 코드 상수로 조정                           |
| 확대 방식 | 최대 프레임 크기를 기준으로 화면에 여백을 두는 공통 배율  |
| 표시 위치 | 화면 중앙을 기준으로 일관된 캐릭터 기준점 적용            |
| 재생 순서 | 시트의 위에서 아래, 왼쪽에서 오른쪽 순으로 동작 그룹 정의 |
| 배경      | 캐릭터와 구분되는 단색                                    |
| 대기 화면 | 직전 동작의 마지막 프레임 유지                            |

## 6. 상태 및 데이터 설계

애니메이션 데이터에는 동작 이름과 순서가 있는 프레임 목록을 둔다. 각 프레임은 잘라낼 영역과 필요한 기준점 정보를 가진다.

재생 상태에는 현재 동작 인덱스, 현재 프레임 인덱스, 완료한 반복 횟수, 프레임 누적 시간, 대기 경과 시간을 둔다. 상태는 `PLAYING`과 `WAITING`으로 나누고, 종료 요청은 어느 상태에서도 처리한다.

프레임 영역은 이미지 경계를 벗어나지 않아야 하고, 모든 동작은 최소 1개의 유효한 프레임을 가져야 한다.

## 7. 범위에서 제외하는 기능

- 게임 플레이, 이동 및 충돌 판정.
- 애니메이션 편집 또는 이미지 수정.
- 동작 선택 메뉴, 배속 UI, 일시정지 기능.
- 사운드, 영상 저장, 추가 스프라이트 지원.

## 8. 단계별 개발 및 커밋 계획

각 단계의 결과를 확인하고 커밋한 뒤 다음 단계로 진행한다. 완성된 코드를 한꺼번에 작성한 뒤 커밋만 나누지 않는다. 아래 22단계를 기본 계획으로 사용하며, 각 커밋은 확인 가능한 변경을 포함한다.

커밋 메시지는 한국어로 변경 내용을 구체적으로 설명한다. 예: `pico2d 캔버스 생성 및 종료 처리 추가`, `동작별 5회 반복 재생 구현`, `마지막 동작 이후 첫 동작으로 순환하도록 수정`.

| 단계 | 작업 및 커밋 단위                                    | 확인 기준                          |
| ---- | ---------------------------------------------------- | ---------------------------------- |
| 01   | 단일 실행 파일과 진입점 생성                         | 실행 진입 가능                     |
| 02   | pico2d 캔버스 생성 및 정리                           | 창 열림 및 정상 정리               |
| 03   | 창 닫기 이벤트 처리                                  | 닫기 버튼으로 종료                 |
| 04   | ESC 종료 처리                                        | 키 입력으로 종료                   |
| 05   | 소스 위치 기준 이미지 경로 구성                      | 다른 작업 디렉터리에서도 경로 정상 |
| 06   | 이미지 로딩 및 실패 메시지 구현                      | 정상 로딩, 누락 시 명확한 오류     |
| 07   | 스프라이트 전체 조사 결과를 코드에 기록              | 동작 목록과 프레임 수 식별         |
| 08   | 프레임 영역 데이터와 좌표 변환 구성                  | 원본의 지정 영역과 일치            |
| 09   | 첫 동작의 정지 프레임 표시                           | 인접 프레임 섞임 없음              |
| 10   | 비율을 유지하는 확대 렌더링 구현                     | 충분한 크기와 화면 내 표시         |
| 11   | 프레임별 기준점 정렬 구현                            | 위치 흔들림 최소화                 |
| 12   | 경과 시간 측정과 갱신 루프 구성                      | 이벤트 처리 지속                   |
| 13   | 첫 동작의 프레임 순환 구현                           | 순서와 속도 정상                   |
| 14   | 반복 완료 횟수 계산 구현                             | 한 사이클당 1회 증가               |
| 15   | 5회 완료 후 재생 상태 전환 구현                      | 정확히 5회 후 대기 진입            |
| 16   | 1초 대기와 마지막 프레임 유지 구현                   | 대기 시간과 표시 정상              |
| 17   | 두 번째 동작 정의 및 전환 구현                       | 다음 동작의 첫 프레임부터 시작     |
| 18   | 나머지 모든 동작 데이터 등록                         | 조사 목록 전체 포함                |
| 19   | 전체 목록 순차 재생 구현                             | 모든 동작에 같은 규칙 적용         |
| 20   | 마지막에서 첫 동작으로 순환 구현                     | 목록 2회 이상 순환 확인            |
| 21   | 프레임 데이터 검증과 단일 프레임 처리 보강           | 잘못된 영역 감지, 경계 사례 정상   |
| 22   | 전체 육안 검증에 따른 표시·타이밍 보정 및 코드 정리 | 아래 완료 기준 충족                |

각 단계 검증에서 발견한 결함은 해당 단계 또는 별도 수정 커밋으로 해결한다. 최종 커밋 수는 최소 20개이며, 검증 때문에 추가한 변경은 별도로 기록할 수 있다.

## 9. 검증 및 완료 기준

- [ ] pico2d가 설치된 환경에서 단일 소스 파일로 실행된다.
- [ ] 소스 폴더 밖에서 실행해도 스프라이트를 정상 로딩한다.
- [ ] 실제 시트에서 조사한 모든 동작과 프레임이 재생 목록에 포함된다.
- [ ] 프레임 잘림, 인접 동작 혼입, 비율 왜곡이 없다.
- [ ] 캐릭터가 충분히 확대되고 모든 프레임이 화면 안에 표시된다.
- [ ] 각 동작의 전체 프레임 사이클이 정확히 5회 재생된다.
- [ ] 5회 재생 후 다음 동작 시작까지 1초 대기한다. 측정 오차는 정상 실행 시 화면 갱신 1회 수준을 허용한다.
- [ ] 대기 중 마지막 프레임이 유지되고 종료 입력이 처리된다.
- [ ] 마지막 동작에서 첫 동작으로 돌아오며 최소 2회의 전체 순환을 확인한다.
- [ ] 한 프레임 동작과 동작 전환 시 반복 횟수 및 타이머 초기화가 정상이다.
- [ ] 창 닫기 및 ESC로 정상 종료된다.
- [ ] 단계별 개발 이력이 최소 20개의 커밋으로 남아 있다.
- [ ] 모든 개발 및 수정 커밋의 메시지가 한국어로 작성되어 있다.

재생 횟수와 시간은 개발 중 임시 로그 또는 상태 추적으로 확인하고, 최종 화면 품질은 실제 실행 화면에서 확인한다. 로그는 프레임마다 출력하지 않도록 하여 재생에 영향을 주지 않게 한다.
